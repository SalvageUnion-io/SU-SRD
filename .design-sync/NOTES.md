# design-sync notes — component-lib → claude.ai/design

Repo-specific gotchas for future syncs. Read this before touching
`.design-sync/config.json`.

## Shape: `package`, not `storybook` — and why Ladle can't stand in

The repo has **530 story files** and a full Ladle catalog (`packages/component-lib/.ladle/`),
but no Storybook. Ladle was evaluated as a fidelity oracle and rejected on a
concrete blocker, not on principle:

- Every story reads `SalvageUnionReference.*` fixtures **at module top level**
  (`.ladle/components.tsx` says so explicitly, and it is true across the set).
- Ladle makes that safe with a `use()` + `Suspense` preload gate that runs
  *before* it dynamically imports a story chunk.
- The design-sync preview harness has no equivalent: `_ds_bundle.js` and each
  `_preview/<Name>.js` are plain classic `<script>` tags with no `await` between
  them, so a story module evaluates immediately and every top-level ORM read
  throws "Schema not loaded".

A shim (`ladle build` + a synthesized `index.json`/`iframe.html`) would solve the
*routing*, and would still leave that blocker untouched. So previews are
**authored** in `.design-sync/previews/`, ported from the Ladle stories with the
ORM reads moved inside the render body. The stories remain the best composition
source in the repo — port from them, don't invent.

## The package ships TS source, so two artifacts are generated for the converter

`component-lib` has **no build step** (`exports["."] = "./src/index.ts"`). Two
things had to be manufactured, both gitignored, both regenerated by `buildCmd`:

- **`packages/component-lib/types/` + `packages/component-lib/index.d.ts`** —
  emitted by `.design-sync/tsconfig.dts.json`. The converter discovers components
  from the shipped `.d.ts` exports and extracts each `<Name>Props` from them;
  with no `.d.ts` tree it found **zero** components and fell back to
  "tokens-only DS".
  - The `index.d.ts` **shim at the package root is required**, not decoration:
    the converter resolves the type entry as
    `<pkgDir>/${package.json types ?? 'index.d.ts'}`, and component-lib declares
    no `types` field. Emitting into `types/` alone is not enough — `findTypesRoot`
    finds the tree but `projectFor` still looks for `<pkgDir>/index.d.ts`. The
    shim points one at the other without editing the package manifest.
- **`packages/component-lib/.ds-css/compiled.css`** — Tailwind v4 output from
  `.design-sync/tailwind-entry.css`. See below.

## CSS: the converter copies, it does not compile

`src/styles/theme.css` is Tailwind v4 **source** (`@theme`, `@utility`) and the
components are written in utility classes, so copying the shipped stylesheets
would ship a design system with no utilities at all. `.design-sync/tailwind-entry.css`
compiles them, and reproduces `apps/itun/src/index.css`'s layer order verbatim
(`@layer reset, theme, base, su-base, components, utilities` + the
`layer(su-base)` import) — that ordering is load-bearing for the same reason
documented in `src/styles/ladle.css`.

**`cssEntry` must resolve INSIDE the package.** Unlike `extraEntries` /
`extraFonts` (bounded to the workspace root), `cssEntry` is bounded to the
package dir — a repo-root path is silently skipped with a `! cssEntry: …` line.
Hence `.ds-css/` inside the package rather than under `.design-sync/`.

### Three dashboard stylesheets are invisible to the converter

`DashboardCanvas.css`, `DashboardGrid.css` and `instruments.css` are **not**
reachable from `index.css` — each is a side-effect `import './x.css'` inside its
own component, which Vite injects for the apps. The converter compiles `.css`
imports to empty (styles ship via the stylesheet, not the bundle), so without
explicit `@import`s in the Tailwind entry the entire `.pc-*` instrument
vocabulary is missing and every dashboard component renders unstyled. They are
imported unlayered and last, which is how a side-effect import lands in an app.

## The ORM must be a bundle export (`extraEntries`)

`salvageunion-reference` is listed in `extraEntries` so preview imports of it
resolve to `window.SalvageUnion.SalvageUnionReference` rather than bundling a
**second copy**. A second copy is a different module instance: the provider
preloads instance A, the preview reads instance B, and every data method throws.
Cost is ~14 KB — esbuild dedupes it against component-lib's own dependency.

This is also a real part of the contract: a design that renders entity
components needs the ORM, and it is now reachable from the bundle.

## `cfg.provider` is a data gate, and it is not optional

`.design-sync/ds-provider.tsx` (`SalvageUnionDataProvider`) wraps every preview
and mirrors `apps/itun`'s `GameDataReady` / `apps/srd`'s `useGameData`. Without
it, components render before `preload('all')` resolves and come up **silently
blank** — not an error.

Deliberately **not** a visual wrapper (no background, padding, or font), unlike
Ladle's `Provider`. A story catalog needs a paper ground; a real page owns its
own layout, and baking one in would frame every design the agent builds.

**Consequence for authored previews:** never read `SalvageUnionReference.*` at
preview-module top level. Read it inside the render body — the provider has
resolved by then. Every ported story needed this change.

## `surface="instrument"` sits on CREAM, never on the dark ground

Hit twice (Button, CountStepper), so it is written down. The dashboard is
"warm-paper instruments on a dark ground" (`instruments.css`): `--color-ink-deep`
goes **behind** everything, `--color-band-cream` is the instrument chassis, and
the instrument variants are ink-on-cream —
`.su-btn--instrument.su-btn--ghost { color: var(--su-color-ink) }`, and
CountStepper's instrument readout is `text-ink`.

Both Ladle stories put these controls straight onto `--color-ink-deep`, which
renders ink-on-ink and is all but invisible. **Do not copy that from the
stories.** Put instrument controls on a band-cream chassis, and put the dark
ground behind the chassis.

## Tooling quirks

- **`npm` is blocked by a repo hook** (`enforce-bun.sh`). The skill's
  `npm i` line for `.ds-sync/` fails outright.
- **`bun add` inside `.ds-sync/` pollutes the ROOT manifest.** Bun treated
  `.ds-sync/` as part of the workspace and wrote `esbuild` / `ts-morph` /
  `@tailwindcss/cli` into the repo's own `package.json` + `bun.lock`. The fix:
  install the converter deps **outside the repo entirely** and symlink them in —
  `.ds-sync/node_modules` → a scratch dir. Check `git diff package.json bun.lock`
  after any install here.
- **Playwright chromium was already cached** (`~/Library/Caches/ms-playwright`),
  matching the repo's pinned playwright 1.62.1. No download was needed.
- The `Bash` cwd drifts between calls in this worktree — pin it per command.

## Known render warns (triaged, not defects)

- **`PageShell` renders on pale blue.** That is correct: `--color-wk-bg` is
  `rgb(230, 240, 245)`, ITUN's real `<body>` background. Not a missing token.
- **`MasonryColumns` — `ViewportLadder` and `TwoColumnCap` look identical.**
  The capture viewport is 900px wide, where the responsive ladder already yields
  two columns. Both cells are honest at that width; the axis only separates
  above `xl`.
- **Tall components need an explicit `overrides.<Name>.viewport`.** The capture
  default is 900x700 and taller cards clip at the cell boundary — cosmetic in the
  sheet, but it hides content from grading. `ReferenceEntityCard` needs
  ~900x1900. Cap is 2000x2000.
- **`[RENDER_THIN]` on `ModalShell` and `SheetPickerModal` is benign and
  permanent.** Both portal their dialog to `document.body`, so the card ROOT
  measures 0px while the dialog itself renders full-size. Verified from the
  screenshots: ModalShell shows the complete pilot-toned dialog (backdrop,
  stamps, close, body) and SheetPickerModal the whole picker (facets, search,
  "SHOWING 82 OF 82", card pool, floating Chosen rail). Do not "fix" these by
  reworking the previews — there is nothing to fix, and both already carry
  `cardMode: "single"`.
- **10 components need `cardMode`, not a bigger viewport.** `[GRID_OVERFLOW]`
  fires when a story is wider than a grid cell (→ `"column"`) or escapes it via
  fixed/portal positioning (→ `"single"`). Both are set in `overrides`; a rebuild
  clears the warning. Column mode also re-flags nothing by construction.

## Capture limits, measured

- **`EntitySearcher` cannot render a large schema under capture.** Entity cards
  emit a responsive `srcSet` of REMOTE candidates (`CardImage` +
  `cardImageSizes`), so a pool of 82 equipment cards fans out to several hundred
  image requests and the capture browser dies outright — `page.setViewportSize:
  Target page, context or browser has been closed`, reproducibly, at every
  viewport tried (1200x1400 → 1000x900) and in both `column` and `single` card
  modes. Chassis is worse still: it carries the heaviest artwork in the set.
  The preview therefore searches `crawler-bays` (14) and `crawlers` (5), both
  real uses of the identical configuration — the story itself names Change
  Crawler Type alongside Change Chassis. **Do not "restore" equipment/chassis
  here without re-checking that it captures**; it silently takes the whole
  validate run down with a `root empty` that looks like a render bug.
- **`package-capture.mjs` over all 94 at once hangs.** It stalled at 39/94 with
  no output and no further file writes. Scoped batches of ~12 are reliable;
  batches of ~24 occasionally report transient errors that clear on a re-run of
  the same set in smaller groups. Prefer `--components` batches.
- **`write_files` drops the socket on large payloads.** A 60-file batch
  containing `_ds_bundle.js` (3.5 MB) fails with `socket hang up` / `Socket is
  closed`. Upload the bundle ALONE, and keep other batches at ~24-30 files. The
  failure is transient and the connection recovers — `list_files` right after
  confirms project state before retrying.

## Re-sync risks

- **Everything under "two artifacts are generated" is gitignored.** A fresh
  clone has no `types/`, no `index.d.ts` shim, no `.ds-css/compiled.css` — run
  `buildCmd` before the converter or discovery silently reports 0 components and
  degrades to a tokens-only DS. That failure is quiet; check the
  `components: N` line in the build log.
- **The Tailwind `@source` set is a guess about consumers.** It scans
  component-lib plus both apps, so the compiled utility set is "what this repo's
  own consumers use". A design the agent writes with a utility no consumer
  happens to use will not resolve. If designs come back unstyled in specific
  spots, widen `@source` or add `@source inline(...)` — do not conclude the
  bundle is broken.
- **Story files are the composition source and they drift.** Previews were
  ported from `*.stories.tsx` at this sync; a story rewritten upstream does not
  invalidate its authored preview automatically. When a component's API changes,
  re-read its story before trusting the existing preview.
- **`Guides` is the only schema carrying `label` content blocks** (4 in the whole
  dataset), and they have no `label` field. `Content`'s cells collect blocks by
  type across schemas for this reason — a single entity is a wall of paragraphs
  (2003 paragraph blocks vs 17 headings, 15 hints, 7 flavor, 4 label).
- **main moves under a long run.** This sync started at `5aa69088` and main had
  advanced ~20 files in `component-lib/src` + the ORM by the time it finished —
  including `index.ts`, `ReferenceEntityCard` (+124), `index.css` (+149) and the
  new `CardImage` srcSet. The uploaded bundle was stale until it was rebuilt on
  the rebased HEAD. **Rebase and rebuild before the final upload**, and re-run
  validate: that rebuild is what surfaced the EntitySearcher capture limit
  above, which did not exist on the older tree.
- **Write-layer stories were deliberately not ported.** `ReferenceEntityCard`'s
  selection / status-cycle / stat-stepper / multi-select stories are all live
  `useState` interactions that a still card cannot show. If those become
  important, they need a settled-state rewrite, not a copy.
