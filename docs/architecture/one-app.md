# One app

`apps/web` is one app ([static pages](../ARCHITECTURE.md#ssg): ADR-050, ADR-065). Its reference pages and the client app differ only in how a page renders, never in how the app is built, served, installed or checked. The page contract is [DESIGN.md](../../apps/web/astro/DESIGN.md).

1. **§1 Two render modes, one source tree** — `src/` holds one component library (`src/components`), one `lib/`, the reference's page modules (`src/reference/pages`, behind `astro/pages/` shells) and the app's routes (`src/routes`, rendered in the browser at `/build/` and `/play/`). Pages stay static islands under the 20 KB JS budget: they never import the router, the stores or the shell.
2. **§2 One build** — Astro owns routing, the build, the dev server, the asset graph and the endpoints (`apps/web/astro.config.ts`); `bun run build` writes `dist/client/` and `dist/server/` (the Worker), the app's shell an Astro page (`astro/pages/build/index.astro`) whose chunks share `assets/`, and no app chunk takes a module a page reaches (`astro/build/appGraph.ts`). After the pages, `@astrojs/sitemap` writes the sitemaps (`astro/build/sitemap.ts`) and `astro/build/site.ts` runs the refusals and the service worker. Bun runs the build; `astro dev` runs under Node 22.23.4+ (Miniflare). Astro pins the Vite major.
3. **§3 Pages are `.tsx`** — An `.astro` file is a five-line shell over a page module, rendered through `astro/lib/reference.tsx`; `tsc` 7 checks the logic and `astro check` the shells (on `@typescript/typescript6` until TypeScript 7.1).
4. **§4 Astro's islands, placed from React** — A page's React tree marks each island (`<Island>`) and `Page.astro` renders it there with `client:*` (`astro/components/Islands.astro`), plus our `client:interaction` and `client:signedIn`. A game-data island cannot hydrate, so it hydrates its stand-in and swaps itself in (`src/runtime/clientSwap.tsx`).
5. **§5 One document head** — Every page and the shell carry the same name, icons and theme colour (`src/lib/documentHead.ts`) and the same bar.
6. **§6 One edge, through the adapter** — Static files behind one Worker (`src/worker/index.ts`, built by `@astrojs/cloudflare`), answering the misses and, through `run_worker_first`, `/build` and `/play`. Its routes are Astro endpoints (`src/worker/routeTable.ts`), so `astro dev` runs it in workerd; one CSP, one `/__errors`, one 404, one sitemap.
7. **§7 One install** — One `site.webmanifest` (scope `/`) and one service worker at `/sw.js` (`src/pwa.ts`) precaching both render modes. While a builder tab is open a new worker waits for it; otherwise it takes over at once (`public/sw-lifecycle.js`).
8. **§8 One set of checks** — One coverage floor, one e2e config, one CI job per kind, one deploy surface (`web`), one changelog stream (`feat(web):`).
