# ADR-007: Automation Boundary — Smart Bookkeeping, No Automatic Destruction

**The app automates resource bookkeeping and enforces the rules. It never
changes an item's condition without explicit player action.**

Auto-applied (non-destructive, recoverable):

- Heat generated by an action; AP/EP spent; uses decremented
  (`activationPatch` in `apps/web/src/lib/rules/actionPatches.ts`, one
  write-through patch).
- Heat clamped to the cap; a Heat Check prompt when heat is gained.
- SP damage from a Reactor Overload (damage = current heat), and other pure
  bookkeeping from the rules functions
  (`packages/salvageunion-reference/lib/rules/heatCheck.ts`).
- Blocking an action when resources are short or its heat would exceed the cap.

Requires explicit player action (destructive, irreversible):

- Any condition change on equipment (intact → damaged → destroyed), only via
  the card's `StatusBadge` (`cycleCondition` in `apps/web/src/lib/rules/mechItems.ts`).
- Destroying a Module or System from any source; catastrophic meltdown.

Roll outcomes that imply destruction surface the choice; they never silently
mutate the sheet. Classify every new combat mechanic against this boundary
before building it. It is why rules functions return results rather than apply
them. [ADR-021](021-cantina-surface-taxonomy.md) scopes it to Guided Play; in
Free Edit the player edits conditions by hand.
