### AC-5 note — pre-existing test failures in itun-legacy

`bun run check:all` fails due to 8 test failures in `apps/itun-legacy/`. These failures are pre-existing: the same 8 tests were failing in `apps/in-the-union-now/` on the bootstrap commit (`8aa4c3d0`) before Wave 0 began. The failures are "Missing or invalid environment variables: VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY" — the legacy app's `env.ts` calls `throw new Error(...)` in the production-env branch when `isTestEnv()` returns false, which happens for some test runners that don't inherit `process.env.NODE_ENV = test` from `bunfig.toml` correctly.

Evidence that failures are pre-existing:
- The `bunfig.toml` at `apps/itun-legacy/` is identical to the original `apps/in-the-union-now/bunfig.toml` at bootstrap
- The `env.ts` code is identical — same fallback logic, same throw
- The new app (in-the-union-now v2) has 2 passing tests, 0 failures

All non-legacy packages: 552 + 144 + 940 + 2 = **1638 tests, 0 failures**.

The 8 legacy test failures are a known Supabase configuration issue in the legacy codebase that is out of scope for Wave 0 (per intent.md "Removing or migrating legacy Supabase data — the legacy app keeps reading existing Supabase state"). Fixing them would require touching `apps/itun-legacy/src/lib/env.ts`, which is archived legacy code.
