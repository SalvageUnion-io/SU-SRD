## Design decisions

### SnapshotView vs re-using Sheet
Built `SnapshotView` as a separate component rather than passing the snapshot payload through Sheet's store injection. Rationale: Sheet's composition-mode resolution requires entityStore + SoftLinks hydration; a snapshot is a frozen object that doesn't need any of that. SnapshotView is simpler, more testable, and avoids coupling the read-only snapshot path to the live store.

### Share URL construction
The share URL is `window.location.origin + /s/<id>`. The server returns the path only (`/s/<id>` is stored for future use — currently the server returns `/api/snapshots/<id>` as the url field; the client constructs the browser-facing `/s/<id>` from the `id` field). v1 only publishes the requested entity (not linked composition) — bundling is a documented polish iteration.

### Dep-injection pattern
All three components (PublishButton, ShareURLDialog, SnapshotView) follow the same dep-injection pattern as existing Wave 4/5 components: injectable props default to production implementations; tests supply stubs directly. No `mock.module()` used anywhere.
