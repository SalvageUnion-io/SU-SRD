## Composition Mode Algorithm

`Sheet.tsx` uses a synchronous IIFE to resolve one of four modes:

| kind | Soft links present | Mode |
|------|--------------------|------|
| mech | outgoing `mech-to-pilot` | wired |
| mech | none | mech-only |
| pilot | incoming `mech-to-pilot` + outgoing `pilot-to-crawler` | wired |
| pilot | incoming `mech-to-pilot` only | wired |
| pilot | outgoing `pilot-to-crawler` only | wired |
| pilot | none | pilot-only |
| crawler | incoming `pilot-to-crawler` | wired |
| crawler | none | crawler-only |

Stand-ins render automatically: `mech-only` shows `<PilotStandIn />`; `crawler-only` feeds `pilots=[]` to `CrawlerSheet` which renders `<CrawlerPilotsStandIn />` internally.

The file is protected by a hook that blocks direct edits. It is regenerated by running the Vite build (which triggers the `TanStackRouterVite` plugin). The PWA plugin fails on sandbox-blocked `/tmp`, but the route tree is written before that plugin runs, so the regeneration succeeds despite the build error exit code.

Command used: `bunx vite build --outDir /tmp/vite-build-out` from the ITUN app directory.

## Dep-Injection Pattern

`Sheet.tsx` accepts optional `entityStore?: EntityLookup` and `softLinkStore?: SoftLinkStore` props. In production these are omitted and the component falls back to `useEntityStore.getState()` and `useSoftLinks`. In tests, snapshot objects are passed directly — no `mock.module()` required.

Test factories:
- `makeEntityStore(entities)` — returns `{ get: (_type, id) => find-by-id | null }`
- `makeSoftLinkStore(links)` — returns `{ softLinks, create: mock(...), delete: mock(...) }`
