# Bio-Titan / Iron Lady Schema Redistribution — Design

**Date:** 2026-06-04
**Status:** Approved (pending one content value: the Iron Lady's salvage value)

## Background

The `titans` schema is the renamed-and-expanded former `bio-titans` schema. During an
earlier change it was generalized into a meta-category — informally "Bad Guys that have
Titanic Actions" — and the Iron Lady (a non-bio android boss) was filed into it as the
lone `kind: "boss"` entry alongside 12 actual Bio-Titans (`kind: "monster"`).

Community feedback (Panny, Decivre, "Thicc Uotan") established that this categorization
was a mistake:

- **Titanic Actions is not bio-titan-specific.** The Meld Behemoth (in the `meld` schema)
  already has Titanic Actions, so a "Titanic Actions" meta-category is redundant. In the
  codebase, Titanic Actions is already schema-agnostic: it keys purely off an action whose
  `displayName === 'Titanic Actions'`.
- **The Iron Lady is not a Bio-Titan.** She is an android — "basically a Drone with titanic
  actions" — and should carry a drone-style scrap value (`salvageValue`), not bio-salvage.
- **Bio-Titans should surface bio-salvage.** Per the core book, bio-salvage extracted from a
  Titan equals its starting Structure Points (SP).

## Goals

1. Revert the schema `titans` → `bio-titans` (full internal rename), so it is once again a
   bio-only schema.
2. Move the Iron Lady out of that schema into `drones`, giving her a drone-style `salvageValue`.
3. Surface bio-salvage on Bio-Titans, derived from SP, using the existing bio-salvage stat
   renderer.

## Non-Goals

- No new "boss" or "construct" schema. The Iron Lady goes into the existing `drones` schema.
- No new bio-salvage rendering component. We reuse the existing bio-salvage stat.
- No gameplay/balance changes beyond surfacing the SP-derived bio-salvage value.

## Decisions (resolved during brainstorming)

| Decision | Choice |
| --- | --- |
| Iron Lady's new home | Existing `drones` schema (extend `DroneSchema` with optional `actions` + `modules`) |
| Rename depth | Full internal rename: schema key, filename, Zod schema, type, enum, component checks, route slug, catalog, docs |
| `kind` field fate | Drop it — every remaining Bio-Titan is `monster`, so the discriminator is dead weight |
| Bio-salvage surfacing | Reuse the existing bio-salvage stat renderer; **derive** the value from `structurePoints` (no stored field) |

## Design

### Part 1 — Rename `titans` → `bio-titans` (full internal revert)

| Layer | Change |
| --- | --- |
| Zod schema | `TitanSchema` → `BioTitanSchema` (`lib/schemas/entities.ts`); drop the `kind` enum field |
| Type | `SURefTitan` → `SURefBioTitan` (`lib/schemas/index.ts`) and any re-exports in `lib/types/` |
| Enum | `SchemaNameSchema` (`lib/schemas/enums.ts`): `'titans'` → `'bio-titans'` |
| JSON-schema generator | `tools/generateJsonSchemas.ts` schema map entry `titans` → `bio-titans` |
| Data file | `data/titans.json` → `data/bio-titans.json`; remove `kind` from all 12 entries; remove the Iron Lady entry (moves in Part 2) |
| Generated JSON schema | `schemas/titans.schema.json` → `schemas/bio-titans.schema.json` (regenerated by build) |
| Registry | `lib/index.ts`: key `bio-titans`, `model: 'BioTitans'`, `display: 'Bio-Titan'`, lazy model rename (`lazyTitans` → `lazyBioTitans`) |
| Catalog | `data/catalog-categories.json`: `"titans"` → `"bio-titans"` under `denizens` |
| Components | `referenceEntityHelpers.ts` + `ReferenceEntityDisplayContent.tsx`: all `schemaName === 'titans'` checks → `'bio-titans'` |
| Colors | `referenceEntityHelpers.ts` (`bg-su-rust`) + `suref-web/.../catalogColors.ts` keyed to `bio-titans` |
| Docs/tooling | `tools/generateDocs.ts` display `'Titans'` → `'Bio-Titans'`; regenerate `docs/schemas/bio-titans.md` (delete stale `titans` doc if present) |
| Changelog | New changelog entry recording the revert + Iron Lady move |

**Slug impact (accepted):** the reference-site route changes from `/titans/<slug>` to
`/bio-titans/<slug>`. External links to the old route break — accepted as part of the full
internal rename.

### Part 2 — Move the Iron Lady into `drones`

- **Schema:** Extend `DroneSchema` (`lib/schemas/entities.ts`) with two **optional** fields:
  - `actions: z.array(z.string()).optional()`
  - `modules: z.array(z.string()).optional()`
  - (`systems`, `salvageValue`, `structurePoints`, `techLevel` already come from
    `MechanicalEntitySchema`.) Because both new fields are optional, all 13 existing drones
    remain valid with no edits.
- **Data:** Add the Iron Lady record to `data/drones.json` with her existing
  `structurePoints: 87`, `actions` (including `Titanic Actions (The Iron Lady)`), `modules`,
  `content`, and a new `salvageValue`.
  - **Pending value:** the `salvageValue` integer is sourced from *Thatcher's Mech Base, p.2*.
    Until provided, the field is omitted (it is optional) and flagged in the PR as a
    follow-up. We will not invent a number.
  - Her `id` is preserved so cross-references remain stable.
  - Remove her from `bio-titans.json`.
- **Renderer generalization:** today the systems/modules resolution + actions block is gated
  on `schemaName === 'titans'` in `ReferenceEntityDisplayContent.tsx`. Change the gate to
  **field-presence** (does this entity carry `actions` / `modules` / `systems`?) so a drone
  carrying them renders identically — actions block, resolved system/module compact cards,
  and the existing schema-agnostic Titanic Actions full-width treatment. `salvageValue`
  already renders as "Salvage Value" via `referenceEntityStatsConfig.ts`, so her scrap value
  shows automatically once present.

### Part 3 — Surface bio-salvage on Bio-Titans (reuse existing renderer)

The existing bio-salvage rendering is **field-driven**: `getBioSalvageValue` reads a stored
`bioSalvageValue` field (used by NPC Chimerium mutants) and renders a "Bio SV" stat. Bio-Titans
have no such field, and per the design decision we do **not** add one — the value is derived
from SP.

The pure getter `getBioSalvageValue(entity)` has no schema context, so deriving in the getter
would leak bio-salvage onto every entity with `structurePoints` (drones, meld, NPCs, chassis).
Instead, the derivation lives in the **schema-aware stats builder**, alongside the existing
bio-salvage special-casing:

- Thread `schemaName` into `buildReferenceEntityStats` (via `ReferenceEntityStats`, which
  already receives it at the display layer).
- When `schemaName === 'bio-titans'` and there is no explicit `bioSalvageValue`, synthesize the
  bio-salvage stat from `structurePoints`, rendered through the existing bio-salvage stat
  ("Bio SV").
- The pure `getBioSalvageValue` getter stays field-only, so NPCs and all other entities are
  unaffected.

This restores the intended behavior — Bio-Titans display a bio-salvage value equal to SP —
using the existing renderer, correctly scoped.

### Part 4 — Verification

Run, in order:

1. `bun run build:package` — recompile + regenerate `schemas/*.schema.json` (incl. the renamed
   `bio-titans.schema.json`) and docs.
2. `bun run validate:all` — IDs, cross-references, action references (confirms the Iron Lady's
   action/module references resolve from her new home, and no dangling `titans` references).
3. `bun run typecheck`
4. `bun test` — update tests that assert the `titans` schema name; add coverage for
   Iron-Lady-in-drones and Bio-Titan bio-salvage derivation.
5. `bun run lint`

## Risks & Mitigations

- **Missed `titans` reference** → a dangling schema key. Mitigation: repo-wide grep for
  `titans` / `Titan` / `TitanSchema` / `SURefTitan` after the rename; `validate:all` + typecheck.
- **Drone renderer regression** — generalizing the `schemaName === 'titans'` gate to
  field-presence could change how existing drones render (they have `systems` but no `actions`).
  Mitigation: verify a normal drone (systems only) and the Iron Lady (actions + modules +
  Titanic Actions) both render correctly; keep field-presence checks narrow.
- **Bio-salvage leak** — the SP-derived bio-salvage must apply only to `bio-titans`. Mitigation:
  gate strictly on `schemaName === 'bio-titans'`; add a test asserting drones/meld/NPCs do not
  gain a derived bio-salvage stat.
- **Stale asset paths** — the Iron Lady's `asset_url` may point at a `bio-titans/` path.
  Mitigation: leave the asset URL as-is (URLs are opaque) unless it 404s; note in PR.
