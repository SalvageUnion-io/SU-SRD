The Stat — Current / Max cell

The chosen direction, canonicalised. One ink-on-paper cell renders every stat — SP, EP, Heat, Cargo, TL — at both sizes. No hatch, no per-stat colour. State is carried entirely by the border colour, the way stats already flag over-cap and modified values.

Data is the real Mule chassis (Workshop Manual p.100): SP 12 · EP 4 · Heat 6 · Cargo 16 · Sys 16 · Mod 2 · TL 1 · SV 7. Full = the vertical value cell; Compact = the horizontal [label | value] cell (compact === horizontal).

01 The cell

A rounded paper cell. Full carries an ink code-tab, the current value big, and a small /max; a single-value stat (no max) just centres its number. Compact is the horizontal cell — ink label, paper value, small /max. Everything is ink on paper — the border is where state will speak (next section).

02 State lives in the border

The fill, text, label and tab never change — only the border colour encodes state. This extends what the component already does (ink default, green at/over max, rust for choice-modified) into one consistent vocabulary, drawn from the warm status ramp. Colour is a treatment overlay, never a second identity hue.

05 Build notes

Turning this into the Stat atom:

  • One state lever. Replace the ad-hoc bg/valueColor/isOverMax overrides with a single state prop ('default' | 'good' | 'modified' | 'caution' | 'critical') that only drives the border colour. Fill/text/tab are constant.
  • Radius. Full uses rounded-panel (6px), compact uses rounded-badge (2px) — staying inside the canonical radius ladder. If we want the book's rounder look, that's a one-token change to discuss, not a per-component hack.
  • Max is optional. With a max → tab + current/max; without → a single centred value. Same component.
  • Rotated “Current”. Shown on Full where it reads like the book's live column; drop it for static stats or when space is tight.
  • Border weight. Full border-rail (2.5px) so the state colour is legible; compact border-chrome (1.5px).
